Especificación de la API REST

Autenticación y Registro (/auth)

POST/auth/authcheck
Comprueba que el endpoint de autenticación está activo.
200: { "message": "Endpoint de autenticación listo" }
POST/auth/register
Registra un nuevo usuario. Envía código de verificación por correo.
201: { "message": "Usuario creado correctamente", "token": "jwt", "id": 1 }
400: Faltan datos obligatorios / Correo ya registrado / Nickname ya registrado
500: Error enviando el correo de verificación / Error registrando el usuario
POST/auth/login
Autentica al usuario con email/nickname y contraseña.
200: { "message": "Login exitoso", "token": "jwt", "user": { ... } }
400: Faltan credenciales
401: Usuario no registrado / Contraseña inválida / Cuenta de Google (sin contraseña local)
403: Cuenta no verificada — debe verificar el correo primero
POST/auth/change/password
Restablece la contraseña del usuario.
200: { "message": "Cambio de contraseña completado" }
400: Faltan credenciales
401: Usuario no registrado en el sistema
422: No puedes usar la misma contraseña
500: Error actualizando la contraseña
POST/auth/verify
Verifica el email con el código de 6 dígitos recibido por correo.
200: { "message": "Correo verificado correctamente.", "token": "jwt", "user": { ... } } o cuenta ya verificada
400: Cuerpo JSON requerido / Sin código pendiente / Código incorrecto
404: Usuario no encontrado
500: Error verificando el correo
POST/auth/resend-code
Reenvía el código de verificación por correo.
200: { "message": "Nuevo código enviado. Revisa tu correo." } o cuenta ya verificada
404: Usuario no encontrado
500: Error enviando el correo / Error reenviando el código
DELETE/auth/delete-account @token_required
Elimina permanentemente la cuenta del usuario autenticado y todos sus datos.
200: { "message": "Cuenta eliminada correctamente" }
404: Usuario no encontrado
500: Error al eliminar la cuenta
POST/auth/google
Autentica o registra un usuario mediante Google OAuth2 (token de Google).
200: { "message": "Inicio de sesión con Google completado", "token": "jwt", "user": { ... } }
400: Cuerpo JSON requerido / Token de Google no proporcionado
401: Token de Google inválido o expirado
500: Error en autenticación con Google

Gestión de Usuarios (/users)

PATCH/users/update @token_required
Actualiza parcialmente el perfil del usuario autenticado.
200: { "message": "Usuario actualizado correctamente." }
400: Correo ya registrado por otro usuario / Nickname ya registrado por otro usuario
404: Usuario no encontrado
500: Error actualizando el usuario
GET/users/user @token_required
Obtiene los datos del perfil del usuario autenticado.
200: { "user": { user_id, first_name, last_name, nickname, email, phone, timezone, profile_img, name_detail, description_detail, severity } }
404: Usuario no encontrado

Módulo de Actividades (/activities)

GET/activities/ @token_required

200: Array de actividades del usuario / Objeto con los datos de la actividad

POST/activities/activity @token_required
Crea una nueva actividad para el usuario autenticado.

400: Datos de actividad inválidos
PATCH/activities/ @token_required
Actualiza parcialmente una actividad existente.
200: Actividad actualizada
404: Actividad no encontrada
DELETE/activities/ @token_required
Elimina una actividad del usuario autenticado.
200: ActividadBox eliminada correctamente
404: Actividad no encontrada
GET/activities/type @token_required
Lista todos los tipos de actividad del usuario.
200: Array de tipos de actividad
POST/activities/type @token_required
Crea un nuevo tipo de actividad.
201: Tipo de actividad creado
400: Datos inválidos
PATCH/activities/type/ @token_required
Actualiza parcialmente un tipo de actividad.
200: Tipo actualizado
404: Tipo no encontrado
DELETE/activities/type/ @token_required
Elimina un tipo de actividad.
200: Tipo eliminado
404: Tipo no encontrado

Analítica e Historial (/history)

GET/history/check

POST/history/calculate @token_required

200: Registro calculado y guardado

Control y Sincronización del Dispositivo (/bot)

GET/bot/check
Comprueba que la API de bot está activa.
200: { "msg": "Api bot lista" }
POST/bot/pair @token_required
Vincula un Focus.Bot al usuario autenticado mediante su dirección MAC.
201: { "message": "Focus.Bot vinculado con éxito", "bot": { id, name } }
403: El bot ya pertenece a otro usuario
500: Error al guardar en la base de datos
GET/bot/getByUser @token_required
Lista todos los bots vinculados al usuario autenticado.
200: { "bots": [ { bot_id, name, mac_address, status, last_sync } ] } o lista vacía
404: Usuario no registrado en el sistema
500: Error en la carga de bots
PATCH/bot/ @token_required
Actualiza parcialmente los datos de un bot (nombre, configuraciones).
200: { "message": "Bot actualizado con éxito." }
404: Bot no encontrado
500: Error editando el bot
DELETE/bot/ @token_required
Desvincula (borrado lógico) un bot del usuario autenticado.
200: { "message": "Bot desvinculado con éxito" }
404: Bot no encontrado
500: Error al desvincular el Bot
POST/bot/command
Envía un comando MQTT de prueba a un Focus.Bot identificado por su MAC address.
200: { "message": "Comando enviado a " }
503: No se pudo reconectar con el Broker MQTT

Desarrollo Hardware y Arquitectura de Firmware

Módulos Electrónicos del Robot

El núcleo electrónico está integrado por el microcontrolador ESP32 (placa NodeMCU) acoplado de manera óptima a periféricos dedicados:

• Pantalla circular TFT de 1.28" (controlador GC9A01) mediante bus SPI.
• Módulo de audio DFPlayer Mini comunicado mediante bus UART con salida a altavoz de 4 Ω.
• Sensor táctil capacitivo TTP223 para el reconocimiento gestual autónomo.

Protecciones de Hardware y Eficiencia

Inserción de una resistencia de 1 kΩ en la línea RX del DFPlayer Mini para erradicar ruidos por picos de tensión residual. Uso estratégico de un transistor NPN BC547 actuando como interruptor Low-Side para conmutar por hardware el pin BLK de la pantalla, logrando apagar físicamente la retroiluminación en modo SLEEP para maximizar el ahorro energético.

Máquina de Estados Finitos (FSM)

El firmware en C++ implementa una FSM jerárquica para controlar de forma asíncrona el comportamiento y expresiones del bot:

• IDLE: Espera activa con animación de parpadeo cíclico (3500ms abierto / 150ms cerrado).
• RQST: Petición entrante, alterna un ojo abierto y otro entrecerrado de forma dinámica.
• FOCUS/REST: Bloques de trabajo y descanso controlando arcos de progreso geométricos.
• SLEEP: Apagado energético y desactiva la retroiluminación tras 10 minutos de inactividad.

Capa de Red y Protocolos de Comunicación

Punto de Acceso y Portal Cautivo

Al arrancar en ausencia de red, entra en modo Access Point (estado AP) levantando un servidor DNS interno y un Portal Cautivo. Proporciona un formulario HTML nativo incrustado en memoria flash que escanea el entorno (redes 2.4 GHz) para guardar de manera persistente en LittleFS las credenciales nuevas.

Sincronización Bidireccional MQTT

Sincronización en tiempo real mediante arquitectura Publish/Subscribe a través de un bróker MQTT aislado por la dirección MAC del hardware:

• Comandos recibidos (Bot se suscribe): focusapp/{mac}/command
• Cambios de estado (Bot publica): focusapp/{mac}/status
• Resultados de sesión (Bot publica): focusapp/{mac}/result

Integridad en el Flujo de Ejecución

La inyección del comando de inicio encapsula parámetros en formato JSON estructurado conteniendo duraciones y metadatos de audio. El dispositivo asume de forma local e independiente la ejecución del tiempo, y al finalizar calcula las métricas publicando el resultado, garantizando la persistencia íntegra de la traza de productividad aun ante microcortes temporales de red.
